# 团队工作区

每个团队对应一个共享工作区。个人空间继续保留原有数据；创建团队不会转移或公开个人数据。

在「设置 → 团队」创建团队后，使用页面顶部的工作区选择器切换个人空间与团队。团队内共享用例、运行记录、问题、插件配置、浏览器服务和通知渠道。现有执行资源仍由部署统一提供。

管理员可以修改团队名称、邀请成员、调整角色和移除成员。普通成员可以使用共享工作区和退出团队；最后一位管理员必须先指定另一位管理员，才能降级或退出。

邀请通过指定邮箱生成链接，由管理员复制并发送给受邀者。链接 7 天内有效，受邀者须使用该邮箱登录或注册，然后接受邀请。邀请使用一次后失效；重新生成会替换旧链接，管理员也可以撤销未接受的邀请。

## 部署

部署前停止 API 和 worker 的写入，执行 `pnpm db:migrate`，随后启动匹配版本的 API、worker、通知及实时事件进程。新增迁移同时更新实时事件和通知触发器，旧版进程不能与新版并行写入。

## 数据与权限

业务记录保留原有 `userId`，并新增 `teamId`。记录属于个人或团队，两种归属互斥；两者均为空表示历史无归属数据。迁移不会改变原有归属。历史数据分配命令只处理这两列均为空的记录。

服务端从登录会话和 HttpOnly 工作区 cookie 解析归属，并逐次验证团队成员资格。移除成员后，其后续请求会被拒绝，现有 SSE 在下一次权限检查时关闭。切换工作区会同步刷新其他标签页；请求会检查页面所属空间，防止旧标签页向新空间提交数据。切换时重新加载页面，清除旧缓存、组件状态及订阅；退出登录会清除当前团队选择。

后台执行、问题生成、通知投递和实时事件沿用记录的工作区归属；集成凭据的加密关联数据也包含该归属，避免跨工作区读取。
