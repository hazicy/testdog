# 登录身份复用

在用例 Settings 的“登录身份”中选择已有身份，或直接新建。选择“不使用登录身份”会从空白浏览器会话开始，适合验证登录、退出或未登录访问。身份管理位于“设置 → 登录身份”，也可直接访问 `/settings#login-identities`。

## 创建与验证

创建身份需要名称、网站、已保存的 Web 登录流程、登录后验证页面和只在登录后出现的成功标志文字。登录流程使用现有用例画板编写，不能引用其他登录身份。创建或编辑流程会打开画板，保存后返回身份配置，保留当前填写内容。不同身份可以引用同一个流程，通过输入覆盖使用不同账号；密码使用 worker 已配置的密钥名称，不填写明文密码。

“保存并验证”先保存配置，再向现有执行队列提交验证。API 不启动浏览器，也不读取 worker 密钥。验证需要运行 `pnpm worker`。管理页显示尚未验证、正在验证、可复用、需要重新登录和验证失败，可以查看验证执行、编辑流程、重新验证或清除登录态。仍被用例引用或有活动执行的身份不能删除；被身份引用的登录流程也不能删除或改为其他网站、原生平台、循环身份引用。

验证失败会显示失败步骤或成功标志检查失败。执行详情将登录准备独立展示，准备失败时业务步骤未开始。登录准备的操作不混入业务录制步骤；完整登录流程可以单独作为普通用例录制调试。

## 运行与缓存

每次执行先检查身份和用例网站是否匹配，再用独立临时 context 验证缓存。有效时以登录态快照创建新的业务 context。无缓存、超过有效期或成功标志未出现时，最多执行一次登录流程并重新检查成功标志。业务执行中的 Cookie、退出登录及其他状态变化不会写回共享缓存，也不会在业务步骤中途重启用例。

缓存保存 Cookie、localStorage 和 IndexedDB，使用现有集成密钥加密。身份归属、配置版本、登录流程更新时间、浏览器提供方、浏览器类型和设备设置共同区分缓存。状态不进入 API、执行环境快照、报告或普通附件；登录准备过程不录像、不采集 trace。使用登录身份的业务执行保留录像，但关闭可能包含认证请求头的 trace。现有敏感输入保护仍适用。

多个 worker 刷新同一缓存时通过数据库租约串行，等待者拿到锁后再次检查缓存，避免重复登录；取消会关闭临时 context 并释放锁。更新身份和清除登录态会使旧刷新结果失效。有效期默认 60 分钟，每次业务执行仍验证服务端登录状态。

此版本仅支持 Web。依赖 sessionStorage 的登录、验证码或人工 MFA 暂不提供自动复用。独立 context 不隔离服务端账号数据；修改同一账号数据或限制单一有效会话的网站，应串行执行相应测试，后续可扩展账号池。

## 部署与接口

先运行 `pnpm db:migrate`，再重启 API 和 worker。API 与 worker 配置相同的 `CASEFORGE_INTEGRATION_SECRET`，未配置时使用 `BETTER_AUTH_SECRET`（至少 32 字符）。密码引用 `PASSWORD` 对应 worker 的 `CASEFORGE_SECRET_PASSWORD`。

- `GET /api/login-identities`：当前用户的身份、关联用例和可选登录流程。
- `POST /api/login-identities`、`PATCH /api/login-identities/:id`：保存身份；编辑携带 `version`，冲突返回 409。
- `POST /api/login-identities/:id/verify`：幂等提交验证，返回 `{ runId }`；已有活动验证时复用该执行。
- `DELETE /api/login-identities/:id/cache`：清除登录态。
- `DELETE /api/login-identities/:id`：删除未被引用且无活动执行的身份。

Web target 的 `loginIdentityId` 为可选字段。不设置该字段时行为保持空白会话。记录只保留引用及非敏感的准备结果；重放使用当前登录配置准备会话，然后重放业务步骤。独立的身份验证执行需要从身份管理页重新发起，不能当作业务录制重放。
