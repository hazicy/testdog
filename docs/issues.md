# 问题追踪

问题描述持续跟进的缺陷，执行记录描述一次测试。一次执行可以关联多个问题，一个问题也可以关联多个执行步骤。

## 数据与权限

- `issues`：标题、描述、状态、分类、严重程度、关闭原因、归属和编辑版本。
- `issue_occurrences`：发现时的执行及步骤引用，用例、目标、环境和证据元数据快照。数据库唯一索引保证同一来源不会重复关联。
- `issue_verifications`：验证来源、回归执行 ID。验证结论由已保存的执行结果计算，不调用模型，不自动关闭问题。

所有 API 必须登录，或在显式免登录模式中使用无归属数据；客户端不能指定归属。关联执行和步骤必须属于当前用户，步骤必须属于指定执行。附件继续通过已有鉴权接口读取，不返回磁盘路径。引用执行使用 RESTRICT 外键，防止删除历史执行时丢失问题证据。

## 状态

待确认（open）、处理中（in_progress）、待验证（pending_verification）、已关闭（closed）。编辑支持调整状态和重新打开；关闭必须选择 fixed、dismissed、duplicate 或 unreproducible 原因，离开已关闭状态会清空关闭原因。

分类：product、test、environment、execution。严重程度：critical、high、medium、low。

PATCH 必须带当前 version。服务端在事务中校验版本并递增；冲突返回 409。客户端表单固定打开时的版本，后台刷新不会放宽并发检查。

## API

| 接口                               | 内容                                                                 |
| ---------------------------------- | -------------------------------------------------------------------- |
| GET /api/issues                    | 接受 q、status、limit、cursor，返回 issues 和 nextCursor             |
| POST /api/issues                   | title、description、category、severity，可选 source: {runId, stepId} |
| GET /api/issues/:id                | 返回 issue、occurrences、verifications                               |
| PATCH /api/issues/:id              | version，加修改字段、status、closeReason                             |
| POST /api/issues/:id/occurrences   | {runId, stepId?}，重复关联返回成功且不新增关联                       |
| POST /api/issues/:id/verifications | {occurrenceId, recordingVersionId?}，返回新 run，HTTP 202            |

创建问题和发起回归接受 Idempotency-Key UUID；相同键和参数返回已有结果，参数变化返回 409。列表使用更新时间与 ID 的游标分页，搜索中的通配符按字面量处理。

## 回归

未指定录制版本时，执行当前用例定义并使用发现时保存的目标配置。指定录制版本时，重放对应发现执行中的版本；归属、版本关系和重放条件复用现有执行服务校验。临时测试或已删除用例可通过保存修正录制版本后重放。

同一问题已有活动回归时，拒绝重复启动。问题行锁防止并发创建多个回归；执行入队、验证关联和问题状态变更在同一事务中提交。问题转为待验证并保留供用户确认的结论。

结果包含 pending、passed、failed、inconclusive。目标步骤通过且完整执行通过、证据归档完整，才视为验证通过；目标失败视为验证失败。节点删除、节点定义变化、断言变化、未执行、取消或证据不完整显示无法验证。无节点标识的历史步骤需要人工检查。没有关联单独步骤的问题，明确显示完整用例通过的结论。

## 界面

运行画板节点和步骤详情均提供“创建或关联问题”。创建自动填写步骤标题、预期、证据摘要和错误；用户补充分类、严重程度及描述。问题详情提供最近一次失败的预期与实际、复现步骤、发现记录表格、原始执行链接、状态编辑和回归入口。可加载来源执行中的保存版本。

列表每 30 秒刷新；详情有活动回归时每 5 秒刷新，其他时间每 30 秒刷新。复用 SWR 和已有请求封装。当前版本按个人数据归属运行，团队指派与外部平台同步尚未加入。

## 自动创建与历史补录

执行结束时，在保存失败状态和证据的同一事务中自动创建问题。失败断言归类为产品缺陷，操作或启动失败归类为执行问题，默认严重程度为一般，等待用户确认。通过和取消不创建问题。

同一用例、步骤/断言和目标配置的重复失败关联已有未关闭问题；已关闭问题再次发生时新建问题。同一执行来源重复处理不新增记录。回归中的目标失败关联原问题，其他失败独立建单。临时执行按各次来源单独创建。

列表支持状态、平台、日期、最近出现/更新排序，显示执行次数和最近环境；详情提供预期/实际、复现步骤、证据及标记已解决。执行详情显示关联问题链接。出现时间使用来源执行结束时间（未结束则使用开始时间）。

历史失败不会通过 GET 接口写入。显式补录的命令、范围和归属规则统一见 [运维操作](deployment.md#显式运维操作)。
